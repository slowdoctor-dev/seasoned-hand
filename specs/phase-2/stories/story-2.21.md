## Goal

Ship the `seasoned-hand` binary — the OS-layer non-negotiable. Every
UI action has a CLI equivalent so the web frontend becomes one of
several frontends, not THE frontend.

> **Risk flag**: 3h budget. If clap surface + HTTP client + tests
> overshoot, split into 2.21a (project / task subcommands) + 2.21b
> (brief / inbox / channel / provenance subcommands).

## Acceptance criteria

- [ ] New binary crate `seasoned-hand-cli` at `crates/seasoned-hand-cli/`.
      Workspace member. `clap = "4"` derived parser. `colored = "2"`
      for TTY output.
- [ ] Subcommands:
      ```
      seasoned-hand --version
      seasoned-hand init                                          # bootstrap ~/.seasoned-hand/
      seasoned-hand server                                        # delegates to seasoned-hand-server bin
      seasoned-hand project list
      seasoned-hand project create <TITLE> [--description ...]
      seasoned-hand project archive <ID>
      seasoned-hand task new "<brief>" [--project ID] [--detach] [--no-auto-confirm] [--open]
      seasoned-hand task list [--project ID] [--status STATUS] [--limit N]
      seasoned-hand task show <ID>
      seasoned-hand task pause <ID> [--durable]
      seasoned-hand task resume <ID>
      seasoned-hand task cancel <ID>
      seasoned-hand task brief <ID>
      seasoned-hand task deliverable <ID> [--open] [--save PATH]
      seasoned-hand task provenance <ID>
      seasoned-hand inbox                                          # list pending briefings
      seasoned-hand brief confirm <BRIEFING_ID>
      seasoned-hand brief edit <BRIEFING_ID> [--editor]
      seasoned-hand brief cancel <BRIEFING_ID>
      seasoned-hand channel list                                   # GET /v1/channels
      seasoned-hand channel test <NAME> [--role intake|delivery|notify]
      seasoned-hand channel logs <NAME> [--tail]                   # streams via WS subscription
      ```
- [ ] Server URL: `SH_SERVER_URL` env or `--server URL`; default
      `http://127.0.0.1:3000`.
- [ ] `task new "<brief>"` blocking-mode: registers via CliChannel
      (in-process if running alongside the server) OR via webhook
      intake (when talking to a remote server). Blocks until
      deliverable arrives. With `--detach`, returns the task_id
      immediately. With `--open`, shells to OS-open on the rendered
      file after delivery.
- [ ] `brief edit --editor`: opens `$EDITOR` (default `vi` / `nano`
      / `vim`) on the current Brief JSON, sends edits via
      `POST /v1/briefings/:id/confirm { action: "edit", edits: ... }`.
- [ ] TTY-color output for status badges (running=blue,
      completed=green, failed=red, paused=yellow, etc.) using
      `colored`. Plain output with `--no-color` or when stdout is
      not a TTY.
- [ ] `--json` flag on any list/show subcommand prints raw JSON for
      scripting.
- [ ] Smoke test in `crates/seasoned-hand-cli/tests/cli_smoke.rs`:
      spawn a server in a test thread (mirrors Phase 1 admin_rollback.rs
      pattern), run each major subcommand, assert exit code 0 + output
      shape.
- [ ] Help text generated by clap. `seasoned-hand --help` and
      `seasoned-hand <cmd> --help` produce useful output. Tested.

## Non-goals

- `seasoned-hand auth login` (Phase 5 multi-user).
- Per-user CLI configuration (Phase 5).
- `seasoned-hand server` actually running the server in-process — it
  delegates to the existing `seasoned-hand-server` binary via
  `std::process::Command::exec`. Avoids re-implementing the server
  bootstrap.
- TUI / curses UI (Phase 5+ stretch).

## Implementation steps

### 1. Crate scaffold

```
crates/seasoned-hand-cli/
  Cargo.toml
  src/
    main.rs              ← clap parser entry
    commands/
      project.rs
      task.rs
      brief.rs
      inbox.rs
      channel.rs
      init.rs
      server.rs
    client.rs            ← HTTP wrapper (reqwest)
    format.rs            ← TTY-color output helpers
  tests/
    cli_smoke.rs
```

### 2. clap structure

`clap::Parser` derive macro. Top-level `Cli { server: Option<String>,
no_color: bool, json: bool, command: Commands }`. `Commands` enum
has one variant per top-level subcommand group.

### 3. HTTP client

`client::ApiClient` wraps `reqwest::Client` + base URL. One method
per route. Same `RouteOutcome` shape on the server side (the CLI
expects `200/202/404/5xx` and prints helpful errors).

### 4. Smoke test

```rust
#[tokio::test]
async fn cli_project_create_then_list() {
    let server_addr = start_test_server().await;
    let output = Command::new(env!("CARGO_BIN_EXE_seasoned-hand"))
        .arg("--server").arg(format!("http://{server_addr}"))
        .arg("project").arg("create").arg("Test Project")
        .output().unwrap();
    assert_eq!(output.status.code(), Some(0));

    let list_output = Command::new(env!("CARGO_BIN_EXE_seasoned-hand"))
        .arg("--server").arg(format!("http://{server_addr}"))
        .arg("--json")
        .arg("project").arg("list")
        .output().unwrap();
    let projects: Vec<Value> = serde_json::from_slice(&list_output.stdout).unwrap();
    assert!(projects.iter().any(|p| p["title"] == "Test Project"));
}
```
